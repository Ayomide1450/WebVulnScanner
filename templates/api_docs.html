API Reference

Every Glassbox capability the web UI offers — assets, scans, reports, compare, and the CI gate — is available as a token-authenticated JSON API under /api/v1, and the glassbox CLI is a thin client over these same routes. This reference is generated from the same spec the server's regression tests lock against the live route table, so it cannot drift from what's actually deployed.

Authentication

Send one of your API tokens as a Bearer header on every request. A token acts as you — it sees exactly what your logged-in session sees, nothing more. Tokens are created and revoked on the API Tokens page and are shown only once at creation.

All errors are JSON ({"error": "..."}), never an HTML page. Responses to token-authenticated requests never set cookies.

Webhooks: verifying signatures

Every webhook delivery carries an X-Glassbox-Signature: sha256=<digest> header — an HMAC-SHA256 of the exact request body bytes, keyed with the per-webhook secret that was revealed once at creation time. Verify it before trusting a delivery:

{{ webhook_snippet }}

Compare against the raw body bytes your framework gives you pre-parsing (re-serialized JSON will not match). Lost your webhook secret? Delete and re-create the webhook — secrets are never rendered again after the initial reveal, and stored URLs are always shown redacted.
