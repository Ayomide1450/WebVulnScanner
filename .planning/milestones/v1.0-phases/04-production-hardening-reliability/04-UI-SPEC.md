# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** HARD-05 only — a **reuse-only visual consistency pass** across four
already-existing pages: `templates/dashboard.html`, `templates/billing.html`,
`templates/org_admin.html`, `templates/scan_report.html`. Per CONTEXT.md's D-10, this phase
introduces **zero new components, colors, or motion patterns**. Every fix below applies a
primitive that already exists in `base.html` (or an already-established convention named in
`CLAUDE.md`'s "Frontend design system" section) to a spot where it is currently missing or where
older, pre-`.btn.primary`/pre-`base.html`-promotion styling was left behind. `scan_progress.html`
is the reference implementation for how `.hud-grid`/`.glow-pulse`/`.telemetry-dot`/`.status-pill`
are meant to look and combine — every recommendation below either reuses an exact class
combination already proven there, or reuses a class in exactly the situation its own `base.html`
comment says it was built for (`.status-pill .dot` is explicitly documented as "additive, absent
from dashboard.html/org_admin.html's plain-text `.status-pill` usage" — i.e. built for this
phase's exact fix).

No new page/route is introduced. No shadcn/component-framework gate applies — same finding as
Phase 1/2/3's UI-SPECs (hand-rolled Jinja2/CSS, no `package.json`/`components.json` in the repo).

### Primary visual anchor per surface touched

Following Phase 3's precedent of naming one anchor per surface rather than texturing every card
on a page (`.hud-grid` in `scan_progress.html` is applied to exactly one card — the Investigation
Log — not every card on that page):

- **`dashboard.html`:** the "Latest scan" card (top card, already hosts the score gauge) is this
  page's anchor. Gets `.hud-grid`.
- **`org_admin.html`:** the "Org scan history" card (the page's most activity-oriented, highest-
  cardinality content) is this page's anchor. Gets `.hud-grid`.
- **`billing.html`:** the "Current plan" summary card (first card on the page) is this page's
  anchor. Gets `.hud-grid`.
- **`scan_report.html`:** no `.hud-grid` change (see Visual Fixes below — this page's gap is
  different in kind, not texture).

## Visual Fixes (page-by-page, the actual HARD-05 work)

This section is the operative part of the contract — the specific, evidence-grounded gap between
each page's current markup and `base.html`'s already-built system, found by reading all four
templates against `scan_progress.html`'s reference usage.

### `dashboard.html`
1. **Replace `.cta` with `.btn.primary`.** The "New scan" link currently uses a page-local `.cta`
   class (`linear-gradient(135deg, var(--accent), var(--accent2))` background + white text) that
   predates `.btn.primary`'s establishment (Phase 1's `scan_new.html`/`asset_detail.html`, Phase
   2's `api_tokens.html`). Swap the class on the `<a>` and delete the now-unused `.cta` rule from
   this page's local `<style>` block.
2. **Add `.hud-grid` to the "Latest scan" card** (`<div class="card">` wrapping the score-gauge
   block) — same `class="card hud-grid"` combination already proven in `scan_progress.html`'s
   `soc-log-card`. Do not add it to the "Your scans" table card or the sparkline card — one
   anchor per page, matching the reference page's restraint.
3. **Add a dot + `.glow-pulse` to running/queued scan-status pills.** For rows (both the "Latest
   scan" summary and the "Your scans" table) where `s.status.value` is `running` or `queued`,
   render `<span class="status-pill {{ s.status.value }}"><span class="dot glow-pulse"></span>{{
   s.status.value }}</span>` instead of the current plain-text-only pill. `completed`/`failed`
   rows are unchanged (no dot) — matches `base.html`'s own note that the dot is "additive."

### `org_admin.html`
1. **Add `.hud-grid` to the "Org scan history" card** — this page's chosen anchor (see Design
   System above), same `class="card hud-grid"` pattern.
2. **Add the same dot + `.glow-pulse` treatment to running/queued rows** in the "Org scan history"
   table, identical logic to dashboard.html's fix #3 above (same `Scan.status` field, same
   component, same visual language — this is literally why `.status-pill` is documented as shared
   between these two pages' tables).
3. **Add `.btn.primary` to the "Send invite" submit button.** Currently relies on
   `_admin_form_styles.html`'s bare `button` selector (an older gradient/white-text pattern). Add
   `class="btn primary"` directly on this page's `<button type="submit">` — a local markup change
   to this one in-scope page, **not** an edit to the shared `_admin_form_styles.html` partial
   (which is also included by `org_verify_domain.html`, out of this phase's named scope — leaving
   the shared partial's bare `button` rule untouched avoids any out-of-scope visual change there).
4. **Members/Domains tables' `.pill.pass`/`.pill.medium` usage is already correct** — no change.
   These already reuse the severity-pill system appropriately (verified→pass green, unverified→
   medium amber) and match `scan_report.html`'s established pill conventions.

### `billing.html`
1. **Add `.hud-grid` to the "Current plan" summary card** — this page's chosen anchor, same
   `class="card hud-grid"` pattern.
2. **Add `.btn.primary` to "Create invoice" and "Verify payment".** Same local-markup-only
   approach as org_admin.html's fix #3 — add `class="btn primary"` directly on these two buttons
   in `billing.html` (composed with `.verify-btn`'s existing compact-sizing modifier for the
   per-invoice verify button: `class="btn primary verify-btn"`). Do not edit the shared
   `_admin_form_styles.html` partial.
3. **Add an "Awaiting payment" `.status-pill.running` to each pending-invoice card**, in the
   `.invoice-row` area alongside "Upgrade to"/"Amount"/"Expires" — this page currently has zero
   telemetry-language despite being the one page in the app whose entire purpose is "waiting on an
   external, not-yet-resolved event," which is exactly `--telemetry`'s reserved meaning elsewhere
   in the app. Optional dot+`.glow-pulse`, matching dashboard/org_admin's running-scan treatment.
4. **Replace the emoji in the no-org `.warn-box` with the new `#icon-warning` SVG symbol**,
   matching `.warn-box .icon`'s existing styling (`color: var(--medium)`) — see Copywriting
   Contract above. This closes `CLAUDE.md`'s explicitly-named leftover for this page.

### `scan_report.html`
This page is already the most visually aligned of the four (Phase 3 added the compliance grouping
toggle, `.pill.compliance`, etc. using the established primitives correctly) — its gap is
different in kind from the other three pages, not a missing-texture/missing-CTA-class gap:

1. **Remove the page-local `table { ... } th, td { ... }` rule** (this page's own `<style>` block,
   currently duplicating `base.html`'s already-promoted `table`/`th, td` rule with **identical**
   values — `width:100%; border-collapse: collapse; font-size: 13px;` /
   `text-align:left; padding: 7px 8px; border-bottom: 1px solid var(--border); vertical-align: top;`
   verbatim). `CLAUDE.md` documents this promotion as covering "four near-identical local
   overrides (dashboard.html/billing.html/org_admin.html/org_verify_domain.html)" —
   `scan_report.html` was missed from that reconciliation and is the one page still carrying dead,
   fully-redundant CSS. This is a pure cleanup (delete 2 lines), not a new rule.
2. **Do not add `.hud-grid`.** Every `.card`-classed element on this page (`.ai-summary-card`) is
   conditionally rendered (only when `r.ai_summary` exists) and already has its own deliberate,
   distinct violet accent per its own header comment ("a one-off violet accent... reads as 'this
   specific section is AI-generated'") — texturing it would blur that intentional distinction.
   `.score-card` itself is not a `.card`-classed element, so applying `.hud-grid` to it would be an
   untested class combination not proven anywhere in the codebase (`scan_progress.html` only ever
   pairs `.hud-grid` with `.card`) — out of this phase's reuse-only mandate. No texture change on
   this page.
3. **`h1`/`h2.section` local top-margin overrides are correct as-is, not dead code** — `base.html`
   explicitly documents per-page top-margin overrides as the intended pattern ("dashboard.html
   keeps a 2-line local override for its extra top margin rather than this changing for
   everyone"). Do not remove these.
