# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** exactly one new UI surface — the **API token-management view**
(`/tokens`, `api_tokens` blueprint per RESEARCH.md): a self-service page where any authenticated
user creates a named token, sees its raw secret exactly once with a copy-to-clipboard affordance
and a clear "won't be shown again" warning, and sees a list of their existing tokens (name,
created date, last-used date, status) with a per-row revoke action. Per CONTEXT.md's D-05, this is
**not** gated to `Role.ORG_ADMIN` — any authenticated org member manages their own tokens.

No other new HTML page is in scope. API-02/03/04 (list assets/status, trigger scan, fetch report)
are JSON-only endpoints under `/api/v1/*` with no browser-rendered surface — they return structured
JSON, not templates, and are explicitly out of this contract's scope. API-06 (the CLI) produces
terminal text output only, not an HTML/visual surface — also out of scope for this visual contract;
the CLI's output formatting is an implementation/UX-copy concern for the planner/executor, not a
design-token concern.

This page **extends** the existing dark-OLED design system already implemented in
`templates/base.html` (fonts, colors, `.card`/`.btn`/`.pill`/`.status-pill`/`.warn-box` component
classes) and follows the same page-scoped-`<style>`-block pattern `templates/asset_detail.html`
(Phase 1) established for new, page-specific classes not promoted into `base.html`
(`.btn.destructive`, `.icon-btn`, disabled-button convention). Zero new visual language is
introduced.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — server-rendered Flask/Jinja2 app (no `package.json`/`components.json`/React/Next/Vite project in the repo). The shadcn initialization gate is **not applicable**, same finding as Phase 1's UI-SPEC. |
| Preset | not applicable |
| Component library | none — hand-rolled CSS in `templates/base.html` plus page-scoped `<style>` blocks. Reuse existing classes (`.card`, `.btn`/`.btn.primary`/`.btn.secondary`/`.btn.destructive`, `.pill`, `.warn-box`, `.table-scroll`, `.icon-btn`, `.field-error`) rather than inventing parallel ones. `.btn.destructive` and `.icon-btn` were introduced page-scoped in `asset_detail.html` (Phase 1, not promoted to `base.html`) — this phase reuses them from that same page-scoped pattern in its own `<style>` block, does not re-invent them. |
| Icon library | none (npm) — hand-authored inline `<symbol>` SVG sprite in `base.html`. This phase adds two new symbols (below), reusing the existing sprite rather than starting a second icon system. |
| Font | Fira Sans (UI/body/headings), Fira Code (mono — the token's raw secret value, table timestamps if monospace-styled elsewhere). Both already loaded in `base.html`; no new font. |

### New icon symbols required this phase

Add to `base.html`'s existing `<svg style="position:absolute...">` sprite, matching the established
stroke convention exactly (`viewBox="0 0 24 24"`, `stroke-linecap="round"`, `stroke-linejoin="round"`,
no fill, `stroke-width:1.8` inherited from `.icon`):

| Symbol id | Used for |
|-----------|----------|
| `icon-key` | Page brand accent / "Generate Token" CTA leading icon / one-time-reveal panel heading icon — the token-management equivalent of Phase 1's `icon-radar` role for Assets |
| `icon-copy` | The copy-to-clipboard button on the one-time secret reveal |

Do **not** add a new icon for "Revoke" — the revoke action is a compact text-label button (see
Copywriting Contract / row layout below), not an icon-only control, so it needs no icon at all.
(If a future revision does add one, reuse `icon-trash` per Phase 1's "don't invent a redundant icon
for the same 'remove access' concept" precedent — but this phase's spec does not require it.)

### Primary visual anchor per new screen

- **Token-management page (default view):** the **"Generate Token" CTA** (`.btn.primary`,
  accent-green, `icon-key` leading icon) is the page's focal point — the only accent-colored
  element above the fold, matching `assets.html`'s "Add Asset" CTA anchor pattern and
  `dashboard.html`'s "New scan" CTA before it.
- **Token-management page (immediately after creating a token):** the **one-time secret reveal
  panel** becomes the temporary focal point, rendered above the CTA/table, using the existing
  amber `.warn-box` treatment (not accent, not destructive) so it reads as "act on this now,"
  distinct from both the green conversion-action color and the red danger color.

### Navigation contract

Add a new top-nav link to `base.html`'s `.nav-links` block, visible to **any authenticated user**
(outside the `current_user.role == Role.ORG_ADMIN` conditional — self-service per D-05), positioned
after "Billing" and before the conditional "Org Admin" link:

```html
<a href="{{ url_for('api_tokens.list_tokens') }}">API Tokens</a>
```

Label: **"API Tokens"** (not "Tokens" alone — disambiguates from a session/auth-token concept a
security-engineer user might otherwise assume).

## Spacing Scale

Declared/used values for this phase's new markup — standard 8pt scale only, reused verbatim from
Phase 1's already-declared scale, no new values introduced:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps (Copy button's icon-to-text gap) |
| `--space-2` | 8px | Compact spacing (status-pill internal gap, token-value-row's input-to-button gap) |
| `--space-4` | 16px | Default element spacing — form field vertical rhythm, one-time-reveal panel internal padding |
| `--space-5` | 24px | Section padding — `.card` gaps, one-time-reveal panel outer margin |
| `--space-6` | 32px | Layout gaps — `h2.section` top margin, page `.wrap` vertical padding |
| `--space-7` | 48px | Not used by this phase's new UI (reserved, pre-existing token) |

This phase introduces **zero new spacing values**.

Exceptions (both **reused, not new** — inherited from pre-existing house convention, same
disposition Phase 1's UI-SPEC already documented and force-approved as project-level exceptions):

- The new Tokens table reuses the shared `table td` rule already defined once in `base.html`
  (pre-existing `7px 8px` cell padding, a non-4pt legacy value). Per Phase 1's confirmed
  project-level exception: this is a whole-app convention that predates and outlives any single
  phase — the new Tokens table stays visually consistent with every other table in the app
  (`dashboard.html`, `assets.html`, `org_admin.html`) rather than diverging to satisfy a
  phase-local spacing-scale count. Not re-litigated here; same disposition applies.
- The compact in-table "Revoke" button reuses `_admin_form_styles.html`'s existing `.verify-btn`
  precedent (`padding: 6px 12px`, also non-4pt) for a small in-row action button — this is an
  **already-established** compact-button convention (used today for org_admin.html's domain
  "Verify" button), not a value this phase invents. Reuse the pattern via a page-scoped
  `.revoke-btn` class with the same `6px 12px` padding, not a new pixel value.

No icon-only controls exist on this page (see icon note above), so the 44px-minimum-touch-target
exception Phase 1 declared for `asset_detail.html`'s pause/resume/delete icon buttons does **not**
apply here — this phase's Revoke control is a labeled text button, not icon-only.

## Typography

This phase declares its own type roles below — the sizes/weights genuinely authored by this
phase's new markup. No new `font-size` or `font-weight` value is introduced anywhere in this phase;
every value below already exists in `base.html`'s (and Phase 1's) type system.

**This phase declares (new-role text this phase authors):**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 13.5px | 600 (semibold) | 1.3 |

Exactly two weights, 400 and 600, cover every piece of genuinely new text this phase writes:
- **Body** (16/400/1.5): intro paragraph explaining what tokens do, empty-state body text, the
  one-time-reveal panel's warning paragraph.
- **Label** (13.5/600/1.3): form field `<label>` ("Name"), table column headers, muted meta text
  ("Last used: —"), the reveal panel's heading line. Button text (14.5px, inherited from the
  existing `.btn` class) is treated as the same Label role, per Phase 1's precedent — not a fifth
  size.

**Inherited (unchanged, pre-existing house convention, out of scope for this phase):**

| Role | Size | Weight | Line Height | Where it appears in this phase's surface |
|------|------|--------|-------------|--------------------------------------------|
| Heading | 24px | 700 (bold — pre-existing `h1` token) | 1.2 | Page `<h1>` — "API Tokens". Not a new role; this phase places existing `h1` markup on a new page, it does not define new heading styling. |

No Display-role (36px/800) text is used this phase — there is no score/gauge/large-number element
on the token-management page.

> **Confirmed design-system exception (project-level, not phase-local) — same disposition as
> Phase 1's UI-SPEC.** `h1`'s pre-existing 700 weight (a third weight beyond this phase's declared
> 400/600) is placed on this new page unchanged, per the same project-level decision Phase 1
> already surfaced to and got confirmed by the user: keep visual consistency with the rest of the
> app rather than diverge each new phase's screens to satisfy a phase-local 2-weight count. This
> exception already exists at the whole-house level (predates this phase); it is referenced here,
> not re-decided.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (`--bg`) | Page background |
| Secondary (30%) | `#0b1220` → `#0f172a` gradient (`--panel`/`--panel2`), `#1e293b` (`--border`) | `.card` backgrounds (token list card, create-token form card), table row backgrounds |
| Accent (10%) | `#22c55e` (`--accent`) | See "Accent reserved for" below |
| Destructive | `#f87171` (`--critical`, reused — this app has exactly one semantic red) | Destructive actions only — see below |

**Accent reserved for:**
- The "Generate Token" primary CTA button (`.btn.primary`, matching Assets'/dashboard's existing
  CTA pattern)
- Links (`a`) — matching global `a { color: var(--accent) }`, unchanged
- The "Active" token-status pill (`.pill.pass` reused as-is — green, matching org_admin's
  "verified"/"yes" convention)
- Focus ring (`:focus-visible`, global, unchanged)
- The `icon-key` brand accent on the page's empty state and CTA icon

**Not accent:**
- The Copy-to-clipboard button is `.btn.secondary` (bordered, neutral) — copying is a supporting
  action inside the one-time-reveal flow, not the primary conversion action, and must not compete
  visually with "Generate Token."
- The one-time-reveal panel itself uses the existing amber `.warn-box` treatment
  (`rgba(251,191,36,.07)` bg / `rgba(251,191,36,.3)` border, `--medium`) — a caution/attention
  color, deliberately **not** accent-green and **not** destructive-red. "Copy this now" is an
  attention state, not a conversion prompt and not a danger.
- The "Revoked" token-status pill is `.pill.info` (muted gray-blue, `--info`) — a neutral/inactive
  past-state indicator, not a warning or danger color (a revoked token isn't an ongoing problem to
  flag red; it's simply inactive).

**Destructive reserved for:**
- The "Revoke" button per active token row (compact `.btn.destructive`/`.revoke-btn`, reusing
  `asset_detail.html`'s exact `.btn.destructive` rgba treatment: `rgba(248,113,113,.09)` bg /
  `rgba(248,113,113,.35)` border / `var(--critical)` text)
- The revoke-confirmation native `confirm()` dialog's underlying action is destructive-framed
  (no separate visual element — see Copywriting Contract's confirmation copy)

**Reused, not new:** No new semantic color is introduced. The amber "caution" color used by the
one-time-reveal panel is the same `--medium`/`.warn-box` value already used elsewhere in the app
(e.g. `billing.html`'s existing warning states) — this phase does not invent a second "attention"
color.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Generate Token"** — creates a new named API token (leading `icon-key` icon) |
| Secondary action — copy | **"Copy"** button; on successful copy, label swaps to **"Copied"** for ~2 seconds, then reverts to "Copy". No accent color change — button stays `.btn.secondary` throughout. |
| Secondary action — revoke (per active row) | **"Revoke"** — compact `.btn.destructive`/`.revoke-btn` in the token's Actions column |
| Form field label | **"Name"** — placeholder text: `e.g. "CI pipeline" or "Personal script"` |
| Intro copy (below `<h1>`) | "Tokens let you authenticate CLI and API requests as yourself, without a browser session. Each token has your exact account permissions — treat it like a password." |
| Empty state heading | "No API tokens yet" |
| Empty state body | "Generate a token to authenticate CLI and API requests as yourself. **Generate your first token →**" |
| Error state — missing name | "Enter a name for this token, e.g. \"CI pipeline\" or \"Personal script\"." |
| One-time reveal — heading | "Copy your token now — it won't be shown again" |
| One-time reveal — warning body | "This is the only time you'll see this token's value. WebVulnScanner stores only a one-way hash of it and can't show it to you again if you navigate away — if you lose it, revoke this token and generate a new one." |
| Table column — Created | Raw rendered `created_at` timestamp, no relative-time formatting — matches every other timestamp column in the app (`dashboard.html`, `org_admin.html`, `assets.html`) |
| Table column — Last used | **"Never"** if `last_used_at` is null; otherwise the raw rendered timestamp, same convention as Created |
| Table column — Status | **"Active"** (renders uppercase via `.pill`'s existing `text-transform:uppercase`) for a non-revoked token; **"Revoked"** for a revoked token. Revoked rows show no Actions-column button — replace with plain muted text, no dead/disabled control. |
| Destructive confirmation (native `confirm()` dialog, same mechanism as `asset_detail.html`'s delete-asset flow) | "Revoke \"{token name}\"? Any request using this token will stop working immediately. This can't be undone." Confirm = browser's native OK; Cancel = browser's native Cancel. No custom modal — matches the existing `confirm(...)` + `e.preventDefault()` pattern in `asset_detail.html`'s script block exactly. |

## UI Considerations

Applicable state considerations resolved: **19 covered, 2 backstop, 0 unresolved**

Elements this phase introduces (classified against the 8-category taxonomy; only categories whose
`applies to element kinds` intersect the element's kind are raised):

- **E1 — Token creation form** (`form`) — single "Name" text field + submit
- **E2 — Token list table** (`list-collection`) — Name / Created / Last used / Status / Actions
- **E3 — One-time secret reveal panel** (`static-content`) — the amber warning panel + raw token
  display, shown only immediately after a successful create
- **E4 — Copy-to-clipboard button** (`interactive-control`), embedded inside E3
- **E5 — Revoke action per row** (`interactive-control`)

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | E1 (unfilled form) | ✅ covered | Standard blank text input, no placeholder-vs-empty ambiguity — matches `org_admin.html`'s invite-member form (no special empty-state treatment needed) |
| empty | E2 (no tokens yet) | ✅ covered | "No API tokens yet" + body copy in Copywriting Contract above |
| loading | E1 (form submit in flight) | ✅ covered | Server-rendered POST+redirect-or-rerender (no AJAX) — reuse the existing `.btn:disabled { opacity:.5; cursor:not-allowed; }` + submit-time JS disable pattern from `asset_detail.html`'s script block |
| loading | E2 | ✅ covered | Not applicable — full server-rendered page load (GET), no client-side async fetch; consistent with every other table page in the app having no loading state |
| loading | E5 (revoke in flight) | 🧪 backstop | Reuse the same submit-time-disable pattern as E1/`asset_detail.html`'s pause/resume/delete forms; flagged for explicit verification since it's a new instance of the same interaction shape, not previously exercised in a table-row context |
| error | E1 | ✅ covered | Missing-name copy defined in Copywriting Contract above; re-shows the form with the existing `.field-error` class, matching `org_admin.html`'s invite-form error convention |
| error | E2 | ✅ covered | Page-load failure falls through to the existing global `500.html` error page — no per-page custom error state, consistent with every other table page |
| error | E5 (revoke fails server-side) | ✅ covered | Surfaces via the existing global flash-message convention (`base.html`'s `{{ 'error-box' if category == 'error' }}`), reused unchanged |
| error | E4 (clipboard API unavailable/blocked) | 🧪 backstop | The token value must always be visible and manually selectable in a `readonly` text input regardless of clipboard-API support, so copy never becomes the *only* way to get the value — flagged for explicit verification that the fallback (manual select/copy) actually works if `navigator.clipboard` throws or is undefined (e.g. non-HTTPS/older browser) |
| populated | E2 | ✅ covered | Reuses `dashboard.html`/`assets.html`'s exact table styling: `<table>` inside `.table-scroll` inside `.card`, hover-row highlight, columns per Copywriting Contract above |
| populated | E3 | ✅ covered | Amber `.warn-box`-derived panel, heading + warning body (Copywriting Contract) + token-value-row (readonly input + Copy button) |
| partial | E2 (mix of active and revoked tokens in one list) | ✅ covered | Status pill (`.pill.pass` "ACTIVE" / `.pill.info` "REVOKED") distinguishes rows; revoked rows lose the Actions-column button per the Copywriting Contract's Status row |
| partial | E2 (token never used) | ✅ covered | "Never" placeholder for `last_used_at`, defined in Copywriting Contract |
| overflow | E2 (long token name in Name column) | ✅ covered | Token names are free text (not a hostname/URL, so no `<code>` styling); apply `word-break: break-word` to the Name column specifically, plus `maxlength="255"` on the create-form's Name input matching the `ApiToken.name` column's `String(255)` limit — bounds worst-case overflow at the source rather than relying on CSS truncation alone |
| overflow | E2, E3 | ✅ covered | Wrap the Tokens `<table>` in `<div class="table-scroll">` per `base.html`'s documented mandatory-for-every-table convention |
| overflow | E3 (raw token value display) | ✅ covered | `secrets.token_urlsafe(32)` produces a fixed-length ~43-character string — render in a `readonly` monospace (`Fira Code`) text input at `width:100%` inside the panel; no truncation logic needed since the length is deterministic, but the input itself still scrolls horizontally rather than wrapping if a narrow viewport can't fit it at the chosen font size |
| zero-one-many | E2 | ✅ covered | Zero → empty state (above); one/many → same table, no singular/plural copy variance needed |
| long-text | E1 (long name entered) | ✅ covered | Native input text scroll during entry; on display (E2), `word-break: break-word` per the overflow row above |
| long-text | E3 | ✅ covered | Fixed-length token string, no long-text risk — see overflow row above |
