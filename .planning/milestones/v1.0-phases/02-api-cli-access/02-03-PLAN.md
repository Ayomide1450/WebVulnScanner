      GET /api/v1/assets, and prints each asset's name and latest scan status.
    - `wvs assets list --token X --api-url Y` uses the explicit flags instead of any stored config.
    - Token/URL resolution precedence for every command: CLI flag > WVS_API_TOKEN/WVS_API_URL env
      var > stored config file value; if none resolve to a token, the command exits nonzero with a
      "run `wvs login` first" message instead of making an unauthenticated request.
  </behavior>
  <action>
Create `cli/__init__.py` as an empty package marker (the `cli/` package is a standalone top-level
directory, a **sibling** of `glassbox/`, not nested inside it - matches
02-RESEARCH.md's Recommended Project Structure and its Architectural Responsibility Map's "Client
(out-of-process) - talks only to the API tier, never touches Flask/DB/models directly").

Create `cli/wvs.py` using `click` (add `click` as a new line in `requirements.txt` - already
resolves transitively via Flask at 8.4.2 in this project's venv per 02-RESEARCH.md's Environment
Availability table, this just makes it an explicit direct dependency) and `requests` (already a
direct dependency, no new line needed). Structure:

- Module-level constants: `DEFAULT_API_URL = "http://127.0.0.1:5000"`, `CONFIG_PATH =
  pathlib.Path.home() / ".wvs" / "config.json"`.
- `_load_config()`: returns the parsed JSON dict from `CONFIG_PATH`, or `{}` if the file doesn't
  exist or fails to parse (never raises - a missing/corrupt config is equivalent to "not logged in
  yet", not a crash).
- `_save_config(data)`: creates `CONFIG_PATH.parent` (`mkdir(parents=True, exist_ok=True)`), writes
  `data` as JSON, then best-effort `os.chmod(CONFIG_PATH, 0o600)` wrapped in `try/except OSError:
  pass` (chmod semantics differ on Windows - this is a defense-in-depth best effort, not a hard
  requirement, and must never crash the command if it fails).
- `_resolve_token(cli_token)` / `_resolve_api_url(cli_url)`: precedence is the `click.option`'s own
  value first (which itself already resolves CLI-flag-over-`envvar=` internally via click's native
  `envvar=` support - use `@click.option("--token", envvar="WVS_API_TOKEN", default=None)` and
  `@click.option("--api-url", envvar="WVS_API_URL", default=None)` on every command that needs
  them, so click itself handles flag-vs-env-var precedence), then fall back to
  `_load_config().get("token"/"api_url")`, then (for `api_url` only) `DEFAULT_API_URL`. If a
  resolved token is still `None`, raise `click.ClickException("No API token found - run `wvs login`
  first, or pass --token / set WVS_API_TOKEN.")` (nonzero exit, clean message, no traceback).
- `@click.group() def cli(): ...` as the top-level entrypoint (module docstring: "wvs - thin CLI
  client for Glassbox's /api/v1 surface. Talks only to the HTTP API, never imports Flask or
  glassbox directly.").
- `@cli.command("login")` with `--token`/`--api-url` options as above (both prompt if not resolved
  via flag/env - use `click.prompt("API token", hide_input=True)` for the token if still
  unresolved after flag/env, but do **not** prompt for `--api-url` if unresolved, just fall back to
  `DEFAULT_API_URL`): calls `requests.get(f"{api_url}/api/v1/assets", headers={"Authorization":
  f"Bearer {token}"})`; on `resp.status_code == 200`, `_save_config({"token": token, "api_url":
  api_url})` and `click.echo("Logged in.")`; else parse `resp.json().get("error", resp.text)` and
  `raise click.ClickException(f"Login failed: {message}")` - write nothing to the config file on
  failure.
- `@cli.group() def assets(): ...` and `@assets.command("list")`: resolves token/api_url,
  `requests.get(f"{api_url}/api/v1/assets", headers=...)`; on 200, iterate `resp.json()["assets"]`
  and `click.echo` one line per asset (name, target_url, latest scan status/risk_score, "no scans
  yet" if `latest_scan` is `None`); on any other status, raise `click.ClickException` with the
  parsed error message (same pattern as `login`) - **wrap every `requests.*` call site in this
  same try/except-and-raise-ClickException shape**, never let a non-2xx response or a network
  error surface as an unhandled Python traceback (the "clear, non-traceback error" must-have).

Create `tests/test_cli.py` using `click.testing.CliRunner` and `unittest.mock.patch` (stdlib, no
new test dependency - matches 02-RESEARCH.md's Package Legitimacy Audit, only `click` was added)
to mock `requests.get`/`requests.post` at the `cli.wvs.requests.get`/`.post` call sites. Cover: (1)

touch the real `~/.wvs/` during tests); (2) `login` with a mocked 401 response exits nonzero and

`assets list` with no stored config and no `--token`/env var exits nonzero with the "run `wvs
login` first" message, making no HTTP request at all.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Local filesystem (`~/.wvs/config.json`) | A locally-persisted API token, readable by anything with local filesystem access to that user's home directory |
| CLI process &rarr; API over HTTP(S) | Token transmitted in the `Authorization` header on every request this CLI makes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-02-11 | Information Disclosure | `cli/wvs.py::_save_config` | medium | mitigate | Best-effort `os.chmod(CONFIG_PATH, 0o600)` after write restricts read access on POSIX; on Windows (this dev environment) file permissions work differently - documented residual gap, not silently ignored: users who need stronger isolation should pass `--token`/`WVS_API_TOKEN` per-invocation instead of using `wvs login`'s stored-config convenience |
| T-02-12 | Information Disclosure | `cli/report.get` stdout | low | accept | Printing a full report JSON to a terminal can leak org findings via screen share or shell history capture - identical exposure to viewing the same report in a browser tab; no CLI-specific mitigation exists without breaking the "pipeable to CI tooling" requirement |
| T-02-13 | Tampering (transport) | CLI &rarr; API | low | accept | Token transits over plain HTTP against `DEFAULT_API_URL` (`http://127.0.0.1:5000`) in local dev; production deployment (Render) terminates real TLS in front of the app per existing `TRUST_PROXY_HOPS` config - same trust model the web UI's session cookie already relies on, not a new gap this CLI introduces |
</threat_model>
