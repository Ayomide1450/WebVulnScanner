# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Reuse-only phase.** WebVulnScanner has a single, existing, documented dark OLED design system
in `templates/base.html` (see `CLAUDE.md`'s "Frontend design system" section). This phase does
**not** introduce new colors, spacing values, typography sizes, or component patterns beyond
extending `input[type=text]`'s existing visual treatment to `<select>` (a new element type, not a
new pattern — see Typography/Spacing below). Phase 6 (Design System Consistency) is sequenced
immediately after this phase specifically so it only has to audit these new templates once, in
final form. Every value below is copied verbatim from `templates/base.html` /
`templates/_scan_form_styles.html` / `templates/scan_progress.html`, not invented for this phase.

## Spacing Scale

Declared values (existing `base.html` custom properties — reused verbatim, all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-text gaps, tight inline padding |
| `--space-2` | 8px | Compact element spacing (e.g. `h1` bottom margin) |
| `--space-3` | 12px | `.warn-box`/`.error-box`/`.info-box` internal padding |
| `--space-4` | 16px | Default element spacing, `.card` internal gaps, `.finding` padding |
| `--space-5` | 24px | Section padding, `.score-card` padding, `.scan-type-grid` gap |
| `--space-6` | 32px | Layout gaps, `.wrap` top padding |
| `--space-7` | 48px | Major section breaks (declared, rarely used) |

Exceptions: none new for this phase. The wizard's step-indicator, domain-picker row, and
type-grid cards must use only these seven tokens (or the existing hardcoded `18px`/`20px`/`22px`
one-offs already present in `_scan_form_styles.html`'s `.card { margin-top: 20px; }` /
`label { margin-top: 18px; }` — those are pre-existing local drift documented in that file's own
comment, not something this phase should either repeat in new code or silently "fix" — fixing
local drift is Phase 6's job, not Phase 5's).

## Typography

Existing `base.html` scale, reused as-is (no new sizes/weights introduced):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 (body default) |
| Small / Label / Hint | 13.5px | 600 (labels) / 400 (hints, `--muted` color) | 1.4 |
| Section label (`h2.section`) | 15px, uppercase, `.08em` tracking | 700 | 1.3 |
| Heading (`h1`) | 24px | 700 | 1.2 |

Notes:
- The app's existing system spans 3 weights (400 regular / 600 semibold for labels, buttons,
  pills / 700 bold for headings) via the imported Fira Sans weight set — documented here as the
  inherited contract, not re-derived to an artificial 2-weight cap.
- Do **not** reintroduce `_scan_form_styles.html`'s old local `h1 { font-size: 26px; }` /
  `.sub { font-size: 14.5px; }` overrides in any *new* wizard template — those were the prior
  single-form pages' drift from `base.html`'s now-canonical 24px `h1`. New wizard step templates
  should render `h1` unstyled (inherit the canonical 24px/700 from `base.html`).
- `.pill`/`.badge`/`.status-pill` text: 11–11.5px, 700 weight, uppercase, `.04em` tracking —
  reused verbatim for the "Included"/"Requires Verified Domain"/"Requires Paid Plan" availability
  labels (SCANUX-03).

## Color

Existing `base.html` palette, reused as-is:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` `#020617` (+ subtle radial gradients) | Page background |
| Secondary (30%) | `--panel` `#0b1220` → `--panel2` `#0f172a` gradient | `.card` backgrounds (domain-picker card, type-grid cards, confirm card), top nav is transparent over `--bg` |
| Accent (10%) | `--accent` `#22c55e` | Reserved for: primary CTA buttons (`.btn.primary` — "Continue", "Start Scan"), the "Included" pill (`.pill.pass`), the active/current step indicator in the wizard stepper, focus ring (`--ring`), the authorized-checkbox accent color, verified-domain success cues |
| Destructive/warning | `--critical` `#f87171` (errors), `--medium` `#fbbf24` (locked/gated state) | `.error-box` (validation failures, unsafe-target rejection), `.pill.medium` for "Requires Verified Domain"/"Requires Paid Plan" labels — **not** a delete/destructive-action color since this phase has no destructive actions (see Copywriting Contract) |

Accent reserved for: primary submit/continue buttons, the "Included" availability pill, the
active wizard-step indicator, input/select focus states, and the authorized-checkbox tick color.
Never used for the locked/gated pill states (those use `--medium`, matching the existing
`scan_new.html`/`scan_new_advanced.html` convention of `pill pass` vs `pill medium`).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (final wizard action) | **Start Scan** (submits the Confirm Authorization step; existing per-type button copy — "Run scan"/"Run advanced checks"/"Run media scan"/"Run API exposure scan" — may be kept as the literal button label per scan type, but the step itself is titled "Start Scan" in the stepper) |
| Step 1→2 CTA | **Continue** (advances from Select Domain to Select Type; disabled until a target is chosen via dropdown or free text) |
| Locked scan-type CTA (SCANUX-04) | **Upgrade to Unlock** — links to `/billing` when gated by tier, or to `org.verify_domain_view` when gated by domain verification (D-03's context-aware branching); never a disabled/greyed-out control with no action |
| In-flight submit state | Button text swaps to **"Starting scan…"** + `disabled`, matching `login.html`/`signup.html`'s existing `btn.disabled = true; btn.textContent = '...'` pattern verbatim — no spinner icon, text-swap only |
| Empty state — no verified domains | Heading: **"No verified domains yet"** — Body: **"Enter a target below, or verify a domain under Organization → Verify domain to have it appear here next time."** (dropdown still renders, showing only a disabled placeholder option; free-text input stays the primary path, per D-01) |
| Error state — unsafe/blocked target | Reuse the exact existing string verbatim (`_unsafe_target_error()` in `scan_routes.py`): *"This target resolves to a private, internal, or unreachable address and cannot be scanned."* / the cross-org-verified-domain variant already in code — rendered in `.error-box`, problem + no further action needed (target is simply rejected) |
| Error state — missing authorization checkbox | Reuse existing string verbatim: *"You must confirm you own or are authorized to test this domain."* |
| View Report reachability (SCANUX-05) | **View Report** — `.btn.primary`, appears on the progress page the instant a poll/SSE tick reports `status === 'completed'`, in the same page context the scan was launched from (no dashboard round-trip required) |
| Destructive confirmation | **N/A** — this phase introduces no delete/destructive actions (domain deletion, invoice actions, etc. are out of scope; the wizard only creates a `Scan` row, same as today) |

## Wizard Structure (interaction contract)

Not a shadcn/component-library concern, but the core interaction contract this phase's
executor/planner must build against — included here since no separate spec exists for it.

**Step indicator:** a 4-node horizontal stepper at the top of `.wrap`, labeled exactly per
SCANUX-01's wording: **Select Domain → Select Type → Confirm Authorization → Start Scan**. Reuse
`.pill`-style typography (11.5px, 700, uppercase) for step labels; the active step uses
`--accent`, completed steps use `--muted` + a checkmark (reuse `#icon-shield` or a simple ✓ via
existing icon sprite conventions — hand-drawn, not emoji), upcoming steps use `--muted` at reduced
opacity. "Confirm Authorization" and "Start Scan" render as two labeled stepper nodes but occupy
a **single screen** (see below) — do not build a separate page solely for the submit button.

**Step 1 — Select Domain:** one `.card` containing the **"Select Verified Domain"** `<select>`
(new element — style it identically to `_scan_form_styles.html`'s existing
`input[type=text]` rule: same padding, border, border-radius, background,
`:focus` → `border-color: var(--accent)` treatment) populated from the org's verified
`DomainVerification` rows (`verified_at IS NOT NULL`, org-scoped, per D-01 — **not** `Asset`
records), stacked or side-by-side with an "— or —" divider above a free-text target `<input
type=text>` (existing style, unchanged) that is equally visible and equally usable, never a
collapsed/hidden "Other" option. "Continue" (`.btn.primary`) advances to Step 2.

**Step 2 — Select Type:** reuse `.scan-type-grid`'s existing 4-card layout verbatim (from
`scan_new.html`), with two content changes only: (a) the base-scan card's title reads
**"Standard Scan"** instead of "Base scan" (SCANUX-03 — route/code names stay `base`/`new_scan_base`
unchanged); (b) every card's tier pill reads exactly **Included** / **Requires Verified Domain** /
**Requires Paid Plan** (`.pill.pass` / `.pill.medium` respectively) instead of the current
tier-jargon strings ("Free tier included", "Org-verified unlocked", etc.). A locked card's CTA
button is **"Upgrade to Unlock"** (`.btn.secondary`, per D-03's context-aware link target) instead
of the unlocked card's "Run scan"-family primary CTA.

**Step 3 — Confirm Authorization + Start Scan (base/media/api types):** one `.card` reusing the
existing pattern verbatim: `.warn-box` "Authorized use only" notice (exact existing copy/icon) →
a compact selection summary (reuse `scan_progress.html`'s `.intel-row` label/value row style —
muted label left, `Fira Code` value right — for "Target:" and "Scan type:") → the existing
`.check-row` authorized checkbox → the **"Start Scan"** submit button (`.btn.primary` or the
existing full-width `button` style from `_scan_form_styles.html`).

**Step 3 deviation — Advanced type (D-02):** selecting "Advanced" in Step 2 routes into the
existing `scan_new_advanced.html` credentialed form unchanged (`.adv-group` sections, its own
`.check-row` + submit button already embedded at the bottom) — this *is* Advanced's combined
"Confirm Authorization + Start Scan" step; do not build a second generic confirm screen after it.
The stepper still shows all 4 labeled nodes for orientation, with the confirm/start pair mapped
onto this existing form's own checkbox+button.

**Locked full-page state (Advanced, when `not can_run_org_verified`):** reuse
`.locked-state`/`.locked-actions` exactly as `scan_new_advanced.html` already implements it
(centered icon, muted body copy, dual `.btn.primary`/`.btn.secondary` actions) — no change needed
to this existing block, just keep it as the wizard's Step 3 render for a locked Advanced
selection.

**Post-launch (SCANUX-05 / D-04):** base scans keep their existing SSE-driven auto-redirect to
`scan_report` on `status === 'completed'`. Advanced/media/api's progress page (currently
polling-free) gains the same behavior via a lightweight interval poll (reusing `/scan/<id>/events`
or a new status-only endpoint — implementation detail, not a visual one) that, on completion,
either auto-redirects like base scans do, or — at minimum — reveals a persistent **"View Report"**
`.btn.primary` on the same page without requiring a manual refresh or dashboard navigation.
