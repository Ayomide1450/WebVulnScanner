<objective>
Expand the proven wizard shell from 05-01 out to the remaining three scan types: media and
API get the same Step 3 treatment the Standard Scan already has, and Advanced gets the D-02
deviation where its existing credentialed form *is* the Confirm Authorization + Start Scan
step.

Purpose: SCANUX-01 says `/scan/new` **and its four sub-pages** present the guided sequence.
After 05-01 only one of the four does. This plan finishes that, replaces the last three
pages' tier-jargon pills with the SCANUX-03 vocabulary via the same helper Step 2 uses, and
closes the input-loss defect where a validation error on the media, API or advanced form
silently blanks everything the user typed.

Output: three restructured launch templates, two small route-layer additions
(`_availability_for`, per-route prefill), and the regression locks proving none of the
server-side gates moved.
</objective>
