<objective>
Establish the single canonical design-token layer (typography scale, spacing scale, radius scale,
container-width tokens, component canon) in `base.html`, then prove it end-to-end by consolidating
the auth-page shared partial to consume it — before fanning the same consolidation out to the other
two form partials and the legal partial. This is the tracer slice for the whole phase: every one of
06-02/06-03/06-04's per-template fixes depends on the tokens and canonical component styles this
plan creates.

Per D-01 (06-CONTEXT.md): this is a refinement of the existing OLED-dark "evolved operator console"
identity, not a rebrand — every value below either formalizes what most of the app already
independently converged on, snaps an isolated outlier to the nearest scale step, or is a deliberate,
justified refinement (documented per-instance below) where the current value reads as cramped or
inconsistent for a "production-grade cybersecurity SaaS" bar. Per D-02: the four container-width
categories are purpose-based, not one universal width, with exact pixel values already resolved in
06-UI-SPEC.md's Container Max-Widths table (Claude's discretion during planning, already exercised).

Purpose: DESIGN-01/02/03/04 all require "exactly one canonical style" per component/scale — but
`base.html` and its three form partials currently each carry a working but independently-drifted copy
of buttons, inputs, typography sizes and radii. This plan is the single point where that drift gets
consolidated into one real source of truth, so every downstream template-level fix in 06-02/03/04 is
just "delete the local override and let the cascade win" rather than re-deciding the values.

Output: `base.html` with the full documented scale + component canon; `_auth_form_styles.html` fully
consolidated as the tracer's proof; `_scan_form_styles.html`/`_admin_form_styles.html`/
`_legal_styles.html` consolidated to match in the expansion task; one Phase-4 test updated to match
the new, intentional post-Phase-6 reality.
