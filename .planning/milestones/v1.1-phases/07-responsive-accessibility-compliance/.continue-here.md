## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Simultaneous multi-agent session-limit death | Multiple parallel `gsd-executor` background agents can die at once when an account-wide Claude usage/session limit is hit mid-task, leaving uncommitted-but-correct work in the shared working tree. | advisory | Before resuming/relaunching a dead agent, always `git status --short` + `git diff` the affected files first — the work is very often complete and correct, just not committed. Verify with a targeted `pytest` run, commit it yourself, *then* resume the agent for whatever remains, rather than relaunching from scratch (which wastes the already-good work). |
| Concurrent-agent `git add .` collisions | Two Wave-2 agents editing different files in the same working tree both used a broad `git add`/`git commit` at nearly the same moment; one agent's commit accidentally swept in the other's staged-but-uncommitted file (happened twice, both times to `templates/scan_report.html`). | advisory | Both times self-corrected cleanly via `git commit --amend`/`git reset --soft` by the agents themselves, confirmed via `git reflog` — no data lost. Not required to fix structurally for Phase 7 (Wave 2 is done), but worth telling any future parallel-wave executor to `git add <specific-file>` rather than `git add .`. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
