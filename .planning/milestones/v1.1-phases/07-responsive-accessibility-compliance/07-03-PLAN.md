<objective>
Convert the three remaining record-list tables on the asset/token surface to D-01's dual-markup
shape, retire asset_detail.html's now-duplicate local `.icon-btn` rule, and settle the second of
A11Y-04's two opacity blind spots with a real contrast measurement.

Purpose: this is the other half of the D-01 conversion, and it carries the phase's single most
dangerous silent-downgrade risk. api_tokens.html's revoke action is guarded by a `confirm()` dialog
wired by class name and a data attribute, not by an inline `onsubmit` - so a card copy that keeps
the `<form>` and the csrf_token but forgets `class="revoke-token-form"` and `data-token-name` looks
completely correct in review while quietly removing the only confirmation in front of an
irreversible token revocation on every phone. It also triages asset_detail.html's two tables
correctly: one is a record list and becomes cards, the other is a two-column diagnostic dump and
stays a table.

Output: three tables rendering a table at desktop and curated cards at phone widths with the
revoke confirm() intact on both paths; one diagnostic table given `<thead>`/`<tbody>` and left
alone; `.icon-btn` deduplicated onto base.html's promoted rule; a measured contrast ratio for
`.pill.not-checked`; a new pytest module locking all of it.

Implements D-01: for the asset/token surface's three record-list tables, mobile renders curated
stacked cards; asset_detail's two-column diagnostic table is triaged out of that treatment per
D-01's own instruction to audit per-table rather than convert blanket.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `api_tokens.revoke_token` POST route | An irreversible, credential-invalidating action. Protected today by a hidden `csrf_token` field, a server-side ownership check, and a client-side `confirm()` dialog wired by the `.revoke-token-form` class plus a `data-token-name` attribute. This plan duplicates its client-side markup into a second block. |
| browser -> `asset.pause_asset` / `asset.resume_asset` / `asset.delete_asset` POST routes | Icon-only, aria-labelled, CSRF-protected asset actions. Not moved into card markup by this plan, but the `.icon-btn` rule they depend on is relocated. |
| user-supplied token/asset names -> `data-token-name` attribute and card text | Free-text names a user typed are interpolated into attribute position in the new card block. |
