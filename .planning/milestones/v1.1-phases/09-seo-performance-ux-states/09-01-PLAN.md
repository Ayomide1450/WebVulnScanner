touched by any other Phase 9 plan - so it runs in wave 1 with no dependencies.

pages fill in and every authenticated page leaves empty.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Public internet (search crawlers, social-media unfurlers) -> `/robots.txt`, `/sitemap.xml`, and the three public pages | Unauthenticated by design - the entire point of this plan is controlling what these anonymous fetchers see and index. |
| `robots.txt`'s Disallow list -> every authenticated route | Advisory only, not an access control - `robots.txt` asks well-behaved crawlers not to index a path, it does not and cannot block a request. This plan changes discoverability, not authorization; every authenticated route keeps its existing `@login_required`/role-decorator/ownership-check gates untouched. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Information Disclosure | A hand-maintained `robots.txt` Disallow list silently drifting from reality as new authenticated routes are added in later phases, leaving a route crawlable-and-indexable (not exploitable, but a real information-hygiene regression) | low | mitigate | D-01: the list is computed from `current_app.url_map` at request time, proven by Task 2's test independently re-deriving the expected blueprint set from the same source rather than copying the route's own logic. |
| T-09-02 | Information Disclosure | `sitemap.xml` accidentally listing a dashboard/scan/org/billing/admin/account URL | low | mitigate | Task 2's sitemap route filters to the `public.` endpoint prefix only, and its test asserts a regression check that none of those path prefixes appear anywhere in the response body. |
| T-09-03 | Tampering (self-inflicted) | An `og:image`/favicon `url_for(..., _external=True)` call resolving to an unexpected scheme/host in production if `PREFERRED_URL_SCHEME`/`SERVER_NAME` are misconfigured | low | accept | Pre-existing app-wide Flask config concern, not introduced by this plan; every other `_external=True` call in the codebase (invite emails, etc.) already depends on the same config. Out of scope here. |

**ASVS level 1, block-on-high.** No high-severity threat is introduced - this plan only changes
what anonymous crawlers can discover and index, never authorization. No production authentication,
authorization, or SSRF-guard code is touched.
