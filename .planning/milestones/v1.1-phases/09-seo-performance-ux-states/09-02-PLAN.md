<objective>
Close STATE-01 (every major page with a first-run/no-data condition shows a real empty-state
message with a clear next action) and STATE-02 (every form shows a distinct in-flight submitting
state) by extracting one shared `_empty_state.html` partial and auditing every form in the app for
the disabled+text-swap pattern login.html already established.

09-CONTEXT.md's D-04 requires exactly one empty-state implementation app-wide, migrating
`dashboard.html`'s and `assets.html`'s existing one-off markup rather than leaving three
implementations. D-05 extends the existing submitting-state pattern to every form - but this
plan's own grounding (see Task 3) found the real gap is narrower than a blanket "add it
everywhere": all four scan-launch forms plus login/signup already have the full pattern;
api_tokens.html and asset_detail.html already disable their buttons but never swap the visible
text; and only the auth reset flow (forgot/reset password), org-admin's invite/domain forms, and
billing's invoice forms have nothing at all. Task 3 states this precisely rather than
re-implementing what already works.

Purpose: reuse-only phase per 09-UI-SPEC.md - two genuinely new markup shapes
(`_empty_state.html`'s CTA-slot API, and this plan's forms), everything else layered onto existing
`.error-box`/`.warn-box`/flash-message components.
Output: one empty-state partial used everywhere a list can be empty; every form in the app that
lacked a submitting-state indicator now has one, in the app's one existing idiom.
</objective>
