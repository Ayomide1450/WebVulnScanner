## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Authenticated user -> new-scan form submission -> `Scan` row creation | The duplicate-guard boundary. The user already passed `@login_required` and the per-scan-type `authorized*` checkbox; this task only decides whether their request creates a new row or reuses an existing one - it does not relax or add any authorization check. |
| Background `threading.Timer` callback -> `Scan` row write | Runs with no request context and no `current_user` - it operates purely on a `scan_id` captured at spawn time inside the same-process app, the same trust level `_run_scan_in_background`'s own thread already has. It writes only `status`/`error_message`/`completed_at` on the one row it was given. |
