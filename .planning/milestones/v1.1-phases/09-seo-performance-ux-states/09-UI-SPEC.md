# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Reuse-heavy phase, two genuinely new component shapes.** Glassbox has a single, existing,
documented dark OLED design system in `templates/base.html` (see `CLAUDE.md`'s "Frontend design
system" section, and Phase 6/7's own UI-SPECs). Per `09-CONTEXT.md`, this phase does **not**
introduce new colors, spacing values, or typography sizes — every value below is copied verbatim
from `templates/base.html`. Two pre-existing `base.html` tokens sit outside this phase's own
standard-scale footprint (`--space-3`/12px, and an earlier drafting error around a 5th font size)
— see the "Inherited exception" notes in the Spacing Scale and Typography sections below for exact
scope; neither is used by this phase's own new markup. Two genuinely new markup shapes are introduced (`_empty_state.html`'s
CTA-slot API per D-04, and numbered-pagination controls per D-03) because no existing partial
covers either; everything else (submitting-state extension D-05, scan-state messaging D-06/
STATE-03, SEO `<head>` tags D-01/D-02) is a copy/behavior change layered onto existing components
(`.error-box`/`.warn-box`/`.info-box`, the flash-message block, the `login.html`/`signup.html`
button text-swap pattern) — not a new visual pattern.

## Spacing Scale

Standard 8-point scale (4, 8, 16, 24, 32, 48, 64) — this phase's two genuinely new component
shapes (`_empty_state.html` partial, pagination controls) are built entirely from these tokens,
no new pixel values invented:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-text gaps — empty-state body's `margin-top` below its title |
| `--space-2` | 8px | Compact spacing — pagination control gaps, empty-state icon-to-title `margin-top` |
| `--space-4` | 16px | Default element spacing, `.card` internal gaps — empty-state partial container sides |
| `--space-5` | 24px | Section padding |
| `--space-6` | 32px | Layout gaps — empty-state partial container top/bottom |
| `--space-7` | 48px | Major section breaks |

### Inherited exception: `--space-3` (12px)

`base.html` also defines `--space-3: 12px`. It is a multiple of 4 but **not** on the standard
8-point scale above. It is a pre-existing token — established by Phase 6's design-system pass,
**not introduced by Phase 9** — and it is used exclusively by `.error-box`/`.info-box`'s existing
internal padding (`padding: var(--space-3) var(--space-4)`, verbatim in `base.html`) and
`.warn-box`'s existing `gap: 12px`. This phase's STATE-03 scan-failed / scan-timed-out /
duplicate-concurrent-scan messages reuse those three boxes verbatim (per the Copywriting Contract
below) and therefore inherit that 12px padding as-is — no new markup declares or introduces it.

**Confirmed not used by this phase's own new markup**: the `_empty_state.html` partial and the
pagination controls draw only from the standard-scale table above. (An earlier draft of this
partial's title `margin-top` used `var(--space-3)`; it has been corrected to `var(--space-2)` —
see New Component Specifications below — specifically so neither new component shape introduces
this exception value.)

Fixing `--space-3` at the token level (renaming it off the 8-point scale, or migrating its two
call sites to a standard value) is deferred to a future `base.html` cleanup pass — that is Phase
6/7-level token work, out of scope for this reuse-only phase per `09-CONTEXT.md`'s domain
statement, and Phase 6/7's own checkpoints are still open per STATE.md.

`dashboard.html`'s existing local `.empty-state { padding: 28px 16px; }` rule is a second,
separate pre-existing drift (28px maps to neither the standard scale nor `--space-3`) — when
migrating it into `_empty_state.html`, round it to `var(--space-6)` (32px) top/bottom, `var(--space-4)`
(16px) sides, closing this drift rather than carrying it into the new shared partial.

## Typography

Existing `base.html` scale, reused as-is (no new sizes/weights introduced):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 15px | 400 | 1.6 |
| Small / muted hint | 13px | 400 (`--muted` color) | 1.4–1.5 |
| Label / Caption (`h2.section`) | 11px, uppercase, `.06em` tracking | 600 | 1.4 |
| Pill / badge / status-pill / button text | 11–14px, uppercase for pills | 600 | 1 (single line) |
| Heading (`h3`, used for empty-state titles) | 16px | 600 | 1.3 |

Notes:
- Two weights only, per the app's actual imported set: **400 regular** (body, hints, muted meta
  text) and **600 semibold** (headings, labels, buttons, pills). No 700/bold weight is used
  anywhere this phase touches.
- Empty-state partial title: reuse the exact inline style `dashboard.html`'s "No security issues
  found" title already uses — 15px, weight 600, `var(--text)` color — promoted into the partial's
  own `.empty-state-title` class rather than repeated as an inline style at each call site.
- Pagination page numbers use `Fira Code` (monospace, matches every other numeric/counter display
  in the app — scan counters, timestamps, gauge numbers) at 13px/600, not `Fira Sans`.

## Color

Existing `base.html` palette, reused as-is:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` `#020617` (+ subtle radial gradients) | Page background |
| Secondary (30%) | `--panel` `#0b1220` → `--panel2` `#0f172a` gradient | `.card` backgrounds; empty-state partial renders inside its parent `.card`/table container, never its own separate panel |
| Accent (10%) | `--accent` `#22c55e` | Reserved for: empty-state CTA button (`.btn.primary`), the active/current pagination page number, focus states on pagination controls, the existing "all clear" checkmark icon in `dashboard.html`'s no-findings empty state |
| Telemetry (in-progress) | `--telemetry` `#38bdf8` | Submitting-state in-flight indicator, if a spinner/pulse is added (see Submitting State below) — distinct from `--accent`'s "success/complete" meaning, matching the existing `.status-pill.running` convention |
| Destructive/warning | `--critical` `#f87171` (errors), `--medium` `#fbbf24` (warnings) | `.error-box` for scan-failed messages (STATE-03); `--medium`/`.warn-box` for the duplicate-concurrent-scan notice (informational, not a failure — see Copywriting Contract) |

Accent reserved for: the empty-state partial's CTA button, the active pagination page indicator,
and focus rings — **not** for pagination's inactive page numbers or Prev/Next controls (those use
`--muted`/`--text` per `.btn.secondary`'s existing treatment), and not for the duplicate-scan or
timeout messages (those are `--medium`/`--critical`, not accent — accent means success/primary
action, not a scan-state condition).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Empty-state partial — dashboard scan history (existing, migrate verbatim) | **"No scans yet."** + CTA **"Run your first scan →"** → `/scan/new` |
| Empty-state partial — dashboard no findings (existing, migrate verbatim) | Title: **"No security issues found"** — Body: **"Your latest scan did not detect any actionable vulnerabilities."** — no CTA (positive/all-clear state, `#icon-check`-in-shield icon) |
| Empty-state partial — assets list (existing, migrate verbatim) | **"No assets yet. Register a domain as an Asset to scan it automatically on a schedule, instead of resubmitting it by hand."** + CTA **"Add your first Asset →"** → `asset.new_asset` |
| Empty-state partial — org-admin members/domains/scans/activity (new adoption, currently bare `<p>` text) | Reuse existing literal strings verbatim ("No members.", "No domains added yet.", "No scans recorded for this org yet.", "No organization activity recorded yet.") inside the partial's title slot, upgrading each to the icon+title(+CTA where one already exists, e.g. domains' "Add one →") shape — wording unchanged, only the container changes |
| Empty-state partial — billing invoices (new adoption) | **"No pending invoices."** — no CTA (informational; the create-invoice form above it is the action) |
| Empty-state partial — API tokens (new adoption, currently bare `<p>`) | Title: **"No API tokens yet"** — Body: **"Generate a token to authenticate CLI and API requests as yourself."** (existing copy, migrate verbatim) |
| Primary CTA (empty-state default pattern) | **"Run your first scan →"** / **"Add your first Asset →"** / **"Add one →"** — each empty-state instance's CTA is a specific verb + noun naming exactly what the user should do next, never a generic "Get started" |
| Pagination — Prev/Next controls | **"Prev"** / **"Next"** (not "Previous" — matches this app's existing terse label convention, e.g. `.pill` text); disabled (not hidden) on the first/last page respectively |
| Pagination — page count context | **"Page {n} of {total}"** shown adjacent to the numbered controls on narrow viewports where showing every page number would overflow (reuse the `.record-card`/dual-markup breakpoint convention from Phase 7 — numbered buttons on desktop, Prev/Next + "Page N of M" text on mobile) |
| Submitting state — scan-launch forms (base/advanced/media/api) | Button text swaps to **"Starting scan…"** + `disabled`, matching `login.html`'s existing `btn.disabled = true; btn.textContent = '...'` pattern verbatim |
| Submitting state — org-admin forms (invite/domain add/verify/schedule) | **"Sending invite…"** / **"Verifying…"** / **"Saving…"** per form — same disabled+text-swap mechanism, present-participle verb matching the action, no spinner icon |
| Submitting state — billing forms (create/verify invoice) | **"Creating invoice…"** / **"Verifying payment…"** |
| Submitting state — account/settings forms (token create/revoke, profile/password) | **"Generating token…"** / **"Revoking…"** / **"Saving changes…"** |
| Error state — scan failed (generic, existing) | Retire the current bare `"Scan failed: {{ scan.error_message }}"` in favor of a specific, recorded reason from `error_message` itself (e.g. a connection/DNS failure vs. an internal exception) — `.error-box`, unchanged visual treatment, more specific copy content only |
| Error state — scan timed out (new, D-06) | **"This scan exceeded its time limit and was stopped."** — `.error-box`, same placement as the existing failed-scan block in `scan_progress.html`, distinct from the generic failed-scan message so a user can tell "something broke" apart from "this took too long" |
| Info state — duplicate concurrent scan (new, D-06) | **"A scan is already running for this target — showing its live progress."** — rendered via the existing flash-message mechanism (`base.html`'s `get_flashed_messages` → `.info-box`, default category) on redirect to the already-running scan's progress page; not `.error-box` (not a failure — the user's request was honored by pointing them at the in-progress scan) |
| Destructive confirmation | **N/A new** — this phase introduces no new destructive actions; existing destructive confirmations (asset delete, token revoke, domain remove) are unchanged |

## New Component Specifications (interaction contract)

Not a shadcn/registry concern, but the two genuinely new markup shapes this phase introduces —
included here since no separate component spec exists for either.

### `_empty_state.html` partial (D-04)

A Jinja macro (not a plain include), following the shared-partial convention
`_scan_form_styles.html`/`_admin_form_styles.html` already established (a dedicated file, not
promoted into `base.html`, even though its selectors are scoped enough to be safe there — kept
separate per D-04's explicit instruction so there is exactly one file to touch when the empty-state
shape changes). Owns its own scoped `<style>` block (migrated from `dashboard.html`'s local
`.empty-state`/`.empty-state .icon` rules, not duplicated).

**Signature:**
```
{% macro empty_state(icon, title, message, cta_label=none, cta_url=none) %}
```

**Structure:**
```html
<div class="empty-state">
  <svg class="empty-state-icon" viewBox="0 0 24 24" aria-hidden="true">{{ icon|safe }}</svg>
  <div class="empty-state-title">{{ title }}</div>
  <div class="empty-state-body">{{ message }}</div>
  {% if cta_label and cta_url %}
  <a class="btn primary" href="{{ cta_url }}">{{ cta_label }}</a>
  {% endif %}
</div>
```

**Visual spec:**
- Container: centered text (`text-align: center`), `padding: var(--space-6) var(--space-4)`
  (32px/16px — see Spacing exception above), lives inside the existing `.card`/table wrapper it
  replaces, never renders its own `.card` background.
- Icon: 28×28px, `color: var(--muted)` by default; the one existing "positive/all-clear" instance
  (`dashboard.html`'s no-findings state) is the only caller that should pass an `--accent`-colored
  checkmark icon instead — a param, not a special-cased second component.
- Title: `.empty-state-title` — 15px/600/`var(--text)`, `margin-top: var(--space-3)`.
- Body: `.empty-state-body` — 13px/400/`var(--muted)`, `margin-top: var(--space-1)`.
- CTA (optional slot): `.btn.primary`, `margin-top: var(--space-4)`, standard 44px touch-target
  floor per Phase 7's A11Y-03 (already guaranteed by `.btn`'s existing padding).
- The CTA slot is the only "new component shape" here in the API sense — every other call site
  already had inline markup close to this; the slot API (`cta_label`/`cta_url`, both-or-neither)
  is what standardizes it into one reusable contract.

### Numbered pagination controls (D-03)

New markup, no existing precedent in this codebase (only `.limit()` caps exist today). Follows
`.status-pill`/`.pill` sizing conventions rather than inventing new button chrome.

**Structure (desktop, ≥`--bp-card` i.e. wider than 430px):**
```html
<nav class="pagination" aria-label="Pagination">
  <a class="btn secondary" href="?page={{ page - 1 }}" {% if page == 1 %}aria-disabled="true" tabindex="-1"{% endif %}>Prev</a>
  <div class="pagination-pages">
    {% for p in range(1, total_pages + 1) %}
    <a class="pagination-page{{ ' active' if p == page }}" href="?page={{ p }}" {% if p == page %}aria-current="page"{% endif %}>{{ p }}</a>
    {% endfor %}
  </div>
  <a class="btn secondary" href="?page={{ page + 1 }}" {% if page == total_pages %}aria-disabled="true" tabindex="-1"{% endif %}>Next</a>
</nav>
```

**Structure (mobile, <430px — dual-markup convention per Phase 7 D-01):**
```html
<nav class="pagination pagination-mobile" aria-label="Pagination">
  <a class="btn secondary" href="?page={{ page - 1 }}" {% if page == 1 %}aria-disabled="true" tabindex="-1"{% endif %}>Prev</a>
  <span class="pagination-count">Page {{ page }} of {{ total_pages }}</span>
  <a class="btn secondary" href="?page={{ page + 1 }}" {% if page == total_pages %}aria-disabled="true" tabindex="-1"{% endif %}>Next</a>
</nav>
```
Both markup blocks coexist in the DOM simultaneously and CSS `@media` selects exactly one, matching
07-CONTEXT.md's D-01 dual-markup pattern already used for tables — not a JS-driven show/hide.

**Visual spec:**
- `.pagination`: `display: flex; align-items: center; justify-content: center; gap: var(--space-2); margin-top: var(--space-5);`
- Prev/Next: reuse `.btn.secondary` verbatim (border-color `--border`, `--text` color, 44px touch
  target) — never `.btn.primary` (pagination navigation is not the page's primary action).
- `.pagination-page`: 32×32px minimum, centered text, 13px `Fira Code`/600, `border-radius: 6px`,
  `color: var(--muted)`; `.active` state (current page): `background: var(--accent-dim); color: var(--accent);` — the only accent usage in this component, reserved for the current-page indicator only.
- Disabled Prev/Next (`aria-disabled="true"`): `opacity: .5; pointer-events: none;` — rendered, not
  removed from the DOM, so screen readers still announce the control exists at page boundaries.
- Every list this phase paginates (scan history, asset list, org members, findings) renders exactly
  one `.pagination` block, placed immediately below its list/table, never above it.

### SEO `<head>` block structure (D-01/D-02 — non-visual, markup contract only)

`base.html`'s `{% block title %}` gains sibling blocks so public pages can populate them and
authenticated pages leave them empty (no visual rendering — `<head>` content only, included here
because it's a shared-template contract this phase's markup changes must follow):

```html
<title>{% block title %}Glassbox{% endblock %}</title>
{% block meta_description %}{% endblock %}
{% block canonical %}{% endblock %}
{% block og_tags %}{% endblock %}
{% block twitter_tags %}{% endblock %}
```

Only `marketing.html`, `terms.html`, `privacy.html` override these blocks (title, 150–160 char
meta description, canonical URL, OG title/description/image/url, Twitter Card tags reusing the OG
values per D-02). Every authenticated template inherits the empty defaults — no dashboard/scan/
org/billing/admin/account page ever emits a meta description, canonical tag, or OG/Twitter tags.
`robots.txt`/`sitemap.xml` (D-01, dynamic routes built from `app.url_map`) and the favicon set
(SEO-04) are non-visual/non-template concerns, not part of this design contract.
