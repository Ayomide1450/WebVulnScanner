<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser → `/assets/<id>/schedule`, `/pause`, `/resume`, `/delete` | Untrusted user-supplied cadence/scan-type input, and state-mutating actions, cross here |
| Session cookie → org-scoped resource | Any authenticated user of one org/solo-account must not read or mutate another org's/solo-account's Asset via these new routes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-01-04 | Information Disclosure / Elevation of Privilege | `webvulnscanner/asset_routes.py::asset_detail, update_schedule, pause_asset, resume_asset, delete_asset` | high | mitigate | Every new route in this plan reuses the same `_check_asset_access` guard 01-01 established before reading or mutating an Asset |
| T-01-06 | Tampering | `webvulnscanner/asset_routes.py::update_schedule` | medium | mitigate | Same fixed allow-list validation as registration (`{"daily","weekly","monthly"}` / `{"base","media","api"}`), reused for schedule edits |
| T-01-07 | Tampering | `webvulnscanner/asset_routes.py::pause_asset, resume_asset, delete_asset` | low | mitigate | All three are POST-only (no GET-triggered mutation); delete is soft (`deleted_at`) so the audit/history trail is preserved rather than destroyed |
</threat_model>
