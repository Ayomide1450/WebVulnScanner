# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the four new/extended surfaces this phase adds — Asset registration
form, Asset inventory list, Asset detail (schedule config + scan history/trend + pause/resume/
delete), and the tier-locked-schedule notice state. All four **extend** the existing dark-OLED
design system already implemented in `templates/base.html`/`templates/dashboard.html`/
`templates/scan_new_base.html` — this phase introduces **zero new visual language**. Every token,
color, component class, and copy convention below is either reused verbatim from those three files
or a minimal, same-convention extension of them.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this is a server-rendered Flask/Jinja2 app (no `package.json`, `components.json`, React/Next/Vite project detected in the repo root). The shadcn initialization gate is **not applicable**. |
| Preset | not applicable |
| Component library | none — hand-rolled CSS in `templates/base.html` (no Bootstrap/Tailwind/component framework). All new markup must reuse existing classes (`.card`, `.btn`, `.pill`, `.status-pill`, `.table-scroll`, `.warn-box`, `.error-box`, `.info-box`, `.locked-state`, `.check-row`) rather than inventing parallel ones. |
| Icon library | none (npm) — hand-authored inline `<symbol>` SVG sprite defined once in `base.html` (`#icon-shield`, `#icon-lock`, `#icon-network`, `#icon-folder`, `#icon-mail`, `#icon-bug`, `#icon-radar`), referenced via `<svg class="icon"><use href="#icon-NAME"/></svg>`. This phase adds new symbols to that same sprite (see below) — never a separate icon system. |
| Font | Fira Sans (UI/body/headings), Fira Code (mono — code/URLs/hostnames/data, scores). Both already loaded via the Google Fonts `@import` in `base.html`; no new font is introduced. |

### New icon symbols required this phase

Add to `base.html`'s existing `<svg style="position:absolute...">` sprite, matching the established
stroke convention exactly (`viewBox="0 0 24 24"`, `stroke-linecap="round"`, `stroke-linejoin="round"`,
no fill, `stroke-width:1.8` inherited from `.icon`):

| Symbol id | Used for |
|-----------|----------|
| `icon-clock` | Cadence/schedule indicator on Asset inventory rows and the schedule-config section header |
| `icon-pause` | "Pause schedule" control |
| `icon-play` | "Resume schedule" control |
| `icon-trash` | "Delete Asset" control |

Reuse the existing `icon-radar` symbol (already themed "scanning/sweep") for the "Add Asset" CTA's
leading icon and for the Asset-detail page's brand accent — do not invent a redundant "target"
icon for the same concept.

## Spacing Scale

Declared values — this phase reuses `base.html`'s existing `--space-*` tokens as-is (no new scale,
no new values):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps (pause/resume/delete button icon spacing) |
| `--space-2` | 8px | Compact spacing (status-pill internal gap, table cell padding) |
| `--space-3` | 12px | Existing established exception to the strict 8pt scale (table cell `padding: 7px 8px` rounds near here; kept as-is, not introduced by this phase) |
| `--space-4` | 16px | Default element spacing — card padding, form field vertical rhythm |
| `--space-5` | 24px | Section padding — `.card` gaps, score-card layout |
| `--space-6` | 32px | Layout gaps — `h2.section` top margin, page `.wrap` vertical padding |
| `--space-7` | 48px | Not used by this phase's new UI (reserved, pre-existing token) |

Exceptions:
- Icon-only pause/resume/delete row controls use a **44px minimum touch target** (padding around
  an 18px `.icon`), matching accessibility guidance — this is a touch-target minimum, not a spacing
  token, applied via button padding.
- `--space-3` (12px) is a pre-existing non-4pt-multiple token already baked into `base.html`; this
  phase reuses it as-is rather than "fixing" it (out of scope).

## Typography

This phase extends the existing multi-role type system rather than introducing a fresh 3-4-size
system — the sizes below are the **subset of already-established tokens** this phase's new UI
needs, reused verbatim (no new `font-size` values are introduced anywhere in this phase):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 13.5px | 600 (semibold) | 1.3 |
| Heading | 24px | 700 (bold — pre-existing `h1` token, not new) | 1.2 |
| Display | 36px | 800 (pre-existing `.latest-score`/gauge-number token, not new) | 1.1 |

Role usage on this phase's new surfaces:
- **Body** (16/400/1.5): flowing copy, hint paragraphs on Asset pages, empty-state body text.
- **Label** (13.5/600/1.3): form field `<label>` (Asset name, target URL, cadence, scan type),
  table column headers, muted meta text ("Next run in 2 days"), button text (14.5px in the
  existing `.btn`/form-button classes — treat as the same Label role, do not introduce a fifth size).
- **Heading** (24/700/1.2): page `<h1>` — "Assets" (inventory page), "Add Asset" (registration
  page), Asset name on the detail page.
- **Display** (36/800/1.1, Fira Code): an Asset's latest risk-score number, **only if** the Asset
  detail page surfaces a prominent score card — reuses `dashboard.html`'s `.latest-score` /
  `_gauge.html`'s `.gauge-num .n` convention exactly; do not invent a new large-number style.

Two primary weights for genuinely new text this phase writes: **400** (body/hints) and **600**
(labels/table headers/emphasis). Weights 700 and 800 are reused only where the existing system
already uses them (`h1`, score displays) — not new weights introduced by this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (`--bg`) | Page background on every Asset page (inventory, registration, detail) |
| Secondary (30%) | `#0b1220` → `#0f172a` gradient (`--panel`/`--panel2`), `#1e293b` (`--border`) | `.card` backgrounds (registration form card, schedule-config card, history table card), Asset inventory row/table backgrounds |
| Accent (10%) | `#22c55e` (`--accent`) | See "Accent reserved for" below |
| Destructive | `#f87171` (`--critical`, reused — this app has exactly one semantic red, do not introduce a second) | Destructive actions only — see below |

**Accent reserved for:**
- The "Add Asset" primary CTA button (`.cta`/`.btn.primary` style, matching dashboard's existing
  "New scan" CTA and scan_new_base's "Run scan" submit button)
- The "Save schedule" primary CTA on the schedule-config form
- Links (`a`) — Asset name links, "View history →" row links, matching global `a { color: var(--accent) }`
- The `COMPLETED` scan-status pill and an "Active" (not-paused) schedule-state indicator
  (`.status-pill.completed` reused as-is)
- Focus ring (`:focus-visible`, global, unchanged)
- The risk-score gauge's high-score arc color (`_gauge.html`, reused unchanged)
- The brand/radar icon accent on Asset-related empty states and the "Add Asset" CTA icon

**Not accent:** "Pause schedule" and "Resume schedule" are both neutral/secondary actions
(`.btn.secondary` — bordered, `var(--text)` on `var(--panel)`), not accent-colored — a schedule
toggle is not a conversion action and must not visually compete with "Add Asset"/"Save schedule".

**Destructive reserved for:**
- The "Delete Asset" button and its icon (`icon-trash`)
- The delete-confirmation prompt's accent border/icon (mirrors `.error-box`'s existing
  `rgba(248,113,113,.09)` background / `rgba(248,113,113,.35)` border treatment)
- Fire-time gate-rejection messaging on a scheduled `Scan` row (SSRF-unsafe target, tier-locked
  schedule) — rendered via the existing `.status-pill.failed`/`td.critical` conventions, reused
  unchanged

**Reused, not new — existing telemetry blue:** `#38bdf8` (`--telemetry`) continues to mean
"in progress" and applies unchanged to a scheduled scan's `RUNNING`/`QUEUED` status pill
(`.status-pill.running`/`.status-pill.queued`) exactly as it already does for manual scans on
`dashboard.html` — this phase must not introduce a different color for the same semantic state.

## Copywriting Contract

Where an existing route already established exact wording for an equivalent gate, this phase
**reuses that copy verbatim** (ASSET-02 requires the same gate, and identical copy keeps the two
entry points indistinguishable in tone/trust to the user).

| Element | Copy |
|---------|------|
| Primary CTA | **"Add Asset"** — registers a domain as a persistent Asset (Asset inventory page), mirrors the existing "New scan" CTA pattern on `dashboard.html` |
| Secondary CTA — schedule config | "Save schedule" |
| Secondary CTA — pause | "Pause schedule" |
| Secondary CTA — resume | "Resume schedule" |
| Empty state heading | "No assets yet" |
| Empty state body | "Register a domain as an Asset to scan it automatically on a schedule, instead of resubmitting it by hand. **Add your first Asset →**" — mirrors `dashboard.html`'s exact existing pattern: *"No scans yet. Run your first scan →"* |
| Error state — missing authorization checkbox | **Reused verbatim from `scan_routes.py:_unsafe_target_error`/`new_scan_base` flow:** "You must confirm you own or are authorized to test this domain." |
| Error state — invalid target | **Reused verbatim:** "Enter a valid domain or URL, e.g. example.com" |
| Error state — SSRF-unsafe target (at registration, and again at every scheduled fire per RESEARCH.md Pitfall 5) | **Reused verbatim:** "This target resolves to a private, internal, or unreachable address and cannot be scanned." |
| Error state — tier-locked schedule (fire-time gate replication per RESEARCH.md Pitfall 1; new copy, no existing precedent) | "This schedule requires a higher plan than your org's current plan. Upgrade in Billing to resume this scan type." — stored as the scheduled `Scan.error_message`, rendered the same way any other `FAILED` scan's error is already shown |
| Empty state — Asset scan history (no scheduled runs yet) | "This Asset hasn't been scanned yet. Its schedule will run automatically at the next {cadence} interval." — **assumes no immediate first scan is triggered at registration** (see UI Considerations below; if the planner instead chooses immediate-first-scan, swap this for the existing `scan_progress.html` live-progress redirect pattern) |
| Empty state — Asset risk-score trend chart | **Reused verbatim from `dashboard.html`:** "Not enough completed scans yet for a trend line." |
| Tier-locked schedule notice (inline, on the schedule-config form itself — mirrors `scan_new_base.html`'s existing locked-checks hint) | "{Scan type} requires a **{tier}** plan. See [Billing](url) to upgrade, or choose a scan type included in your current plan." |
| Destructive confirmation | **Delete Asset:** "Delete {asset name}? This stops all scheduled scans for this target. Past scan history is kept for your records." Confirm button: **"Delete Asset"** (destructive/red). Cancel button: **"Cancel"** (ghost/secondary). |
