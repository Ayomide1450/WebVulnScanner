## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `?next=` query parameter -> `redirect()` `Location` header | The open-redirect boundary. Reached via `login_manager.login_view`'s automatic `?next=` generation, so any unauthenticated user can craft the link - the classic phishing setup where the victim sees a genuine login page on the real domain and is then bounced off-origin. |
| an unhandled exception or aborted request -> the HTTP response body a user sees | The information-disclosure boundary. Under `DEBUG=True` this leaks source, locals and an interactive console; under `DEBUG=False` it should leak nothing. Never once exercised by this repo's tests. |
| a developer's local `.env` or an API-key literal -> a git commit -> a public or shared repository | The secrets boundary. Unlike the others, a credential that crosses it cannot be un-crossed by editing the file - it needs rotation. |
