<objective>
Convert org_admin.html's four record-list tables and org_verify_domain.html's Domains table to
D-01's dual-markup table/card shape, and close the one genuine A11Y-01 form-label gap in the
codebase.

Purpose: these five tables carry every destructive, CSRF-protected action in the org surface -
resend invitation, revoke invitation, request domain deletion, verify domain. They are the highest
risk half of D-01's conversion, because a careless row-to-card rework is exactly how a
CSRF-protected POST becomes a bare link. They are also where the codebase's single unlabelled form
control lives (org_admin.html line 136's `reason` input: no label, no id, no aria-label - verified
by an exhaustive input/label audit this planning session).

Output: five tables rendering a semantic table at desktop widths and a curated stacked-card list at
phone widths, every POST form and csrf_token preserved verbatim, the `reason` input given an
accessible name in both markup blocks, and a new pytest module locking all of it.

Implements D-01: for the org surface's five record-list tables, mobile renders curated stacked
cards rather than a horizontally-scrolled table - the scroll-container precedent is deliberately
not extended to these.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `org.resend_invitation` / `org.revoke_invitation` / `org.request_domain_deletion` / `org.verify_domain_view` POST routes | Four state-changing, org-scoped actions. Each is protected today by Flask-WTF CSRF via a hidden `csrf_token` field, plus server-side org-membership/role checks in `org_routes.py`. This plan duplicates the *client-side markup* of all four into a second block. |
| record data -> `aria-label` attribute values | Domain names and emails, both user-supplied at creation time, are now interpolated into attribute position rather than only element-text position. |
